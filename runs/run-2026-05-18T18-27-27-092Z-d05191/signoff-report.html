Approval And Traceability

Only approved test cases should be promoted to automation. Rejected test cases should remain visible for audit, but they must not be converted to scripts or included in sign-off execution coverage. The final report should show approval status and execution status separately.

Error Handling And Evidence

Generated scripts should capture screenshots for each approved test case and allow Playwright to surface failures through assertions. Error output, screenshot paths, duration, and generated spec path should be included in execution evidence for user sign-off.

PW-SCRIPT-002

Modular Script Structure

Scripts should separate arrange, act, and assert steps. Reusable setup and journey logic should be extracted into helper functions with clear method signatures. Tests should not duplicate long setup sequences when a shared helper can express the same business precondition.

Source: RAG://playwright-automation-guidelines#modular-structure | Score: 0.5181

PW-SCRIPT-001

Playwright Naming Convention

Generated Playwright tests should preserve the approved test case ID in the test title. Helper functions should use verb-object names such as completeFintechJourney, submitKycDetails, runFraudCheck, or captureEvidence. File names should be stable, lowercase, and describe the suite purpose.

Source: RAG://playwright-automation-guidelines#naming | Score: 0.46

Locator And Assertion Standards

Prefer stable locators such as data-testid, role, label, placeholder, and visible text in that order. Avoid brittle CSS paths when a semantic locator is available. Every test should contain explicit assertions for the approved expected result, not only page navigation.
